# R5 面试题目生成（Spring AI + RAG + Skill，默认 DeepSeek）

> 来源：`requirements.md` §4
> 阶段：阶段三 | 难度：⭐⭐⭐⭐ 中高 | 依赖：AI 能力层（R5/R6/R8 共用）

## 1. 定位

基于某份简历一键生成「面试官可能问的问题 + 参考答案 + 考察点」，用于面试准备。技术栈选用 **Spring AI**：通过 **RAG（检索增强生成）** 引入题库 / JD 语料提升题目相关性，通过 **Skill（函数化技能）** 将「出题 / 答案与考察点 / JD 解析」拆为可复用、可插拔的原子能力，模型按意图自动编排。

## 2. 前置：AI 能力层（Spring AI，R5/R6/R8 共用）

- **统一版本**：`spring-ai-bom` 管理版本；对话走 OpenAI 兼容协议直连 DeepSeek（`spring-ai-openai-spring-boot-starter` + `base-url=https://api.deepseek.com`，`model=deepseek-chat`）。后续换供应商仅切 `ai.provider` 对应 starter 与 base-url。
- **`ChatClient` Bean**：统一封装一次性调用、流式（`stream()` → SSE）、结构化输出（`BeanOutputConverter` + JSON Schema）。
- **`EmbeddingModel`**（RAG 向量化）：**DeepSeek 无 embedding 端点**，需独立配置——远程 OpenAI 兼容 `text-embedding-*` 或本地 `BGE`/`Ollama`；`rag.enabled=false` 时整体跳过。
- **`VectorStore`**：`rag.store.type=memory|redis|pgvector`，默认 `memory`（`SimpleVectorStore` 文件持久化，零额外依赖），随数据规模演进到 Redis/向量库。
- **可开关降级**（沿袭「可选依赖」约定）：`ai.enabled=false`（无密钥优雅降级）、`rag.enabled=false`（跳过检索直连 LLM）、每个 skill 可独立启停。

配置示例（`AiProperties` + `RagProperties`）：

```yaml
ai:
  provider: deepseek                 # deepseek | openai | qwen（可插拔）
  openai:
    base-url: https://api.deepseek.com
    api-key: ${AI_API_KEY}           # 环境变量注入，不写明文
    chat-model: deepseek-chat
  embedding:
    provider: openai                 # openai | ollama | none
    model: text-embedding-3-small
    api-key: ${EMBEDDING_API_KEY}
  enabled: false                     # 无密钥时优雅降级，返回明确错误
rag:
  enabled: false                     # 是否启用检索增强
  store:
    type: memory                     # memory | redis | pgvector
  top-k: 5
  min-score: 0.65                    # 相似度阈值，低于则不给上下文
```

- **治理**：请求限流、token 用量记录、超时熔断、输入输出内容安全。（现状与规划详见 `R5-A-AI调用健壮性与治理.md`）

## 3. 功能点

1. **选简历 → 定向生成**：指定目标岗位 / 粘贴 JD 后，先经 RAG 检索相关知识，再由 LLM 生成结构化题库。
2. **题库结构**：`[{ category, question, answer, tips }]`，按 category（项目深挖 / 技术原理 / 行为面 / 场景题…）分类。
3. **Skill 编排**：出题、参考答案 + 考察点、JD 解析分别由独立 skill 完成，可单独重跑、按需组合。
4. **结果管理**：保存为「面试题集」，可查看 / 重新生成 / 导出（JSON / Markdown / 文本）。

## 4. RAG 与 Skill 设计（R5 增量）

### 4.1 RAG 知识库（`ai_kb_entry`，按 `kb_type` 区分）

| kb_type | 内容 | 用途 |
|---------|------|------|
| `interview_q` | 高频面试题库（按岗位 / 技术栈 / 难度分级） | 出题 few-shot / 考察维度 |
| `jd` | 岗位 JD / 任职要求语料 | 提炼考察点，定向出题 |
| `skill_prompt` | 各 skill 的 prompt 模板（`code` 定位） | 热更新，不发布代码 |

### 4.2 检索链路

1. 组装检索 query：`目标岗位 + 简历片段（项目/技能/经历）+ 任务意图`。
2. `EmbeddingModel` 向量化 → `VectorStore` top-k 相似检索（`min-score` 过滤）。
3. 检索结果作为 few-shot / 上下文拼入对应 skill 的 prompt。
4. LLM 生成 → 结构化解析，校验失败重试（带容错解析）。

### 4.3 Skill 编排（Spring AI 函数化，`@Tool`）

每个 Skill = 独立 prompt 模板 + I/O JSON Schema + 可选关联工具；通过 `@Tool` 暴露，模型在 `ChatClient.prompt().tools(...)` 中按意图自动路由。

| Skill | 职责 | 输出 |
|-------|------|------|
| `interview.gen_questions` | 出题（结合 RAG 命中的高频题/考察维度） | `[{category, question}]` |
| `interview.gen_answer` | 生成参考答案 + 考察点 | `{answer, tips}` |
| `interview.jd_extract` | 解析 JD，提炼技能点 / 考察维度 | `{skills[], focuses[]}` |

## 5. 数据模型

```sql
-- 知识库（RAG 用，R5/R6 共用；向量由 VectorStore 托管，MySQL 仅存元数据与原文）
CREATE TABLE ai_kb_entry (
  id         BIGINT   NOT NULL AUTO_INCREMENT,
  kb_type    VARCHAR(32) NOT NULL COMMENT 'interview_q/jd/resume_sample/skill_prompt',
  code       VARCHAR(64) DEFAULT NULL COMMENT '技能编码(prompt类)或文档唯一键',
  title      VARCHAR(200) DEFAULT NULL,
  content    TEXT      NOT NULL,
  metadata   JSON      DEFAULT NULL COMMENT '标签/岗位/难度/技术栈等',
  status     TINYINT   NOT NULL DEFAULT 1 COMMENT '1启用 0禁用',
  created_at DATETIME  NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uk_type_code (kb_type, code),
  KEY idx_type_status (kb_type, status)
) ENGINE=InnoDB;

-- 面试题集（沿用）
CREATE TABLE interview_set (
  id BIGINT NOT NULL AUTO_INCREMENT, user_id BIGINT NOT NULL, resume_id BIGINT NOT NULL,
  title VARCHAR(100) DEFAULT NULL, target_role VARCHAR(100) DEFAULT NULL,
  questions TEXT COMMENT '结构化题库 JSON',
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id), KEY idx_user (user_id)
) ENGINE=InnoDB;
```

## 7. 前端改动

新增「面试准备」入口（编辑器按钮 + 独立页），分类卡片展示、导出、流式打字机效果；生成时可填目标岗位 / 粘贴 JD。

## 8. 验收标准

- 选择简历后可生成结构化题库，内容与简历相关（RAG 命中上下文生效）。
- 指定目标岗位 / JD 后题目更定向；结果可保存 / 查看 / 导出 / 删除。
- `rag.enabled=false` 降级为纯 prompt 生成仍可用；`ai.enabled=false` 返回明确错误。
- 限流 / 超时 / 密钥缺失均有明确错误码。

## 9. 难点与风险

- **DeepSeek 输出 JSON 稳定性**：`BeanOutputConverter` + JSON Schema + 重试 + 容错解析。
- **embedding 缺口**：DeepSeek 无 embedding 端点，需另配模型（远程/本地），冷启动数据量小先用内存向量库。
- **RAG 检索质量**：切片粒度、`top-k`、`min-score` 需调优；条目需人审 / 去重。
- **Skill 路由准确性**：多技能下 function calling 的意图识别需校验与兜底回退。
- **token 成本**：检索上下文 + 生成计入配额，需限流与计费。
- 个人信息脱敏后调用 LLM。
