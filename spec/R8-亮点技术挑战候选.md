> 来源：`requirements.md` §4
> 阶段：阶段四 | 难度：高/视项 | 依赖：渲染引擎抽象（A）、AI 网关（B）

## 1. 定位

候选池，按「差异化 + 可行性」排序，含模板绘制/市场这一已明确后置项。

## 2. 候选清单

| 候选 | 一句话 | 价值 | 技术挑战 |
|------|--------|------|----------|
| A. 模板可视化绘制 + 市场 | R4 建表后，允许 `type=user` 自定义模板，拖拽布局 + 字段绑定，发布/审核/一键用 | 高（生态） | 渲染引擎抽象 + Schema 安全 |
| B. AI 简历评分 + JD 匹配度 | 输入 JD 量化匹配度（ATS 打分）+ 建议 | 高（付费） | 评分模型 + 可解释性 |
| C. 简历版本历史/时光机 | 保存快照，diff 回放/回滚 | 高（体验） | 版本存储与 diff |
| D. 分享页 SEO/社交卡片 | 公开分享/社区详情 SSR 快照（OpenGraph） | 中（传播） | SSR/无头渲染 |
| E. 简历水印防爬 | 导出/查看加水印 + 盲水印溯源 | 中（安全） | 盲水印算法 |

> 候选 A~E 均已展开为详细 spec：`R8-A1/A2/A3`（模板编辑器 / 渲染引擎 / 市场）、`R8-B` AI 简历评分与 JD 匹配度、`R8-C` 简历版本历史 / 时光机、`R8-D` 分享页 SEO / 社交卡片、`R8-E` 简历水印防爬。本文件保留候选池总览。

## 3. 推荐顺序

先 A（承接 R4 模板表、复用 AI 网关，分解为 R8-A1 → R8-A2 → R8-A3）→ B → C → 其余按需。

## 4. 落地原则

候选池不作为固定承诺，按「差异化 + 可行性 + 资源」按需启动；A 已明确与 R4 关联（当前 R4 仅建表 + 内置三套，可视化编辑器另立阶段，避免范围蔓延）。
